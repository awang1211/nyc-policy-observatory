# 从官方数据到研究结论：演示脚本

## 0–1 分钟：研究问题与范围

“我研究纽约市报告的服务需求与行政处理情况如何变化，以及哪些部门—服务—社区组合值得进一步调查。研究期是 2025 年 10 月至 2026 年 9 月，对照前一年相同季节。政策响应是另一条研究线，目前官方证据覆盖不足，所以我明确展示缺口。”

## 1–3 分钟：数据从哪里来，怎么变成指标

展示官方 [NYC Open Data 311 入口](https://data.cityofnewyork.us/resource/erm2-nwe9.json) 及仓库 `observatory/ingest.py`。入口是可复查的数据源，不代表本轮重新获取过原始数据。

流程：Socrata 元数据/字段检查 → 按月和请求 ID 分页 → 原始响应来源记录与哈希 → SQLite 请求 ID 去重和更新 → 逐月源端计数核对 → `metrics.py` 计算 → `validate.py` 独立 SQL 对账 → 验证通过后 `load-postgres` 发布 Neon → `analyze.py` 汇总与筛选 → `model/cubes/` 定义查询 → Cube dashboard。

展示 [生产流程运行](https://github.com/awang1211/nyc-policy-observatory/actions/runs/40741460079)：311 获取、指标验证、Neon 发布步骤成功。软件测试使用人工边界样本，负责验证算法；生产验证负责真实数据，两者不能互相替代。当前工作区不含完整原始数据库，不能现场声称又重跑了 755 万条。

指标解释：30 天是 720 个实际小时；纽约浮动时间转 UTC。剔除负结案时长，不把还没有足够观察时间的请求放入结案率分母；基准期采用对应研究期日期的成熟条件。请求量仍保留晚期请求。方法文档写午夜 cutoff，而生产流程配置为 2026-10-27 18:20 纽约时间；最终应以生产 artifact 确认并统一，不隐瞒差异。

## 3–5 分钟：全市结论与行政区比较

展示 `ResearchSummaryView`：基准期 3,595,690 条，研究期 3,963,901 条；增加 368,211 条，约 10.24%。加权 30 天行政结案率由 91.0042% 降至 90.3500%，下降约 0.6542 个百分点。

这是报告量上升、行政结案指标略降的描述，不能据此断言需求总量增长同样比例或政策失效。

然后看 `BoroughComparisonView`：每次说清两期、请求量与分母。请求增长率和结案率变化是不同单位。Unspecified 包含在全市总量里，五区图可以排除但需注明。

## 5–7 分钟：追踪一个调查线索

在 50 条线索中找 DOB → Boilers → QUEENS → 13 QUEENS。保存结果显示：基准期 38 条合格请求，37 条在 30 天内行政结案；研究期 47 条合格请求，10 条在 30 天内行政结案。比例约 97.37% → 21.28%。

“这是值得调查的异常，不是已经查明的部门失败。我会先核实分类、路由和结案记录规则是否变化，再看月度分布、重复请求及官方运营记录。它来自筛选后的极端组合，样本小，也不能代表整个 DOB。”

注意：这一行在线 dashboard 中的位置和筛选联动尚未实查。若页面未就绪，使用 `reports/current-analysis.json` 展示同一行，并明确这是保存的结果。

## 7–8 分钟：政策研究与证据边界

展示来源覆盖表和 [政策流程失败记录](https://github.com/awang1211/nyc-policy-observatory/actions/runs/40741460163)。失败发生在真实记录检查，后续发布跳过；不能只展示其他绿色步骤便宣称政策数据齐全。

政策案例需要官方 URL、事件日期、原文、审核人；宣布、立法和实施分别记录。少量案例只能证明这些案例的阶段，不能证明政策全貌。ACS 任务步骤成功也不证明有可用人口分母；目前没有接受的社会经济分析证据。

## 8–10 分钟：复现与下一步

展示仓库 Actions、方法文档、保存结果核对与 Cube 字段说明。强调实际刷新路径在 GitHub Actions 中使用已有安全配置，不能把本地空数据验证当作生产重跑。

离线可运行：

```bash
python3 scripts/check_saved_analysis.py
python3 -m unittest discover -s tests -v
npm test
```

保存结果核对只检验总量、月度/行政区相加、分母与比例、50 条线索的算术和排序，不重新证明原始数据完整性。

正式分析流程会重写 Neon 分析表；全量加载可能耗时数小时，展示前不随手触发。需要刷新时先确认时间截止点、旧版本备份及运行完成顺序，再获取 → 验证 → 发布 → 分析 → 模型 → 页面验收。

## 演示前必须关闭的事项

- Cube 登录与观众权限、具体图表和筛选行为逐项实查。
- 生产验证 artifact 内容与 cutoff 确认，统一文档时间。
- 保存分析与当前 Neon / Cube 数字一致。
- 政策覆盖缺口、社会经济限制始终可见。
- 完成截图或导出备份；检查数字、日期与敏感信息。
