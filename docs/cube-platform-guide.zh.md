# 如何阅读这个项目的 Cube 平台

## 先认清入口

- [现有 dashboard](https://anruow.cubecloud.dev/d/1/dashboard/KNqY4COMgche)：用户确认已经有雏形；本轮工具尚不能打开登录态页面，具体菜单、图表和链接未实查。
- [Cube 工作区入口](https://anruow.cubecloud.dev/d/1)：项目管理入口。不要把工作区网址当成数据查询 API。
- [GitHub 仓库](https://github.com/awang1211/nyc-policy-observatory)：获取、计算、模型和文档的版本记录。
- [GitHub Actions](https://github.com/awang1211/nyc-policy-observatory/actions)：每次获取、验证、分析和模型检查的运行证据。

下面解释项目涉及的功能类别，**不是对当前账户菜单名称或所有可用功能的实查清单**。具体位置以登录后界面为准，不凭网址猜测深层链接。

## 四层关系

| 层 | 在本项目里做什么 | 你什么时候需要看 |
|---|---|---|
| 数据源：Neon PostgreSQL | 保存已计算的服务指标和研究分析表 | 怀疑数据缺失、刷新失败、权限或连接异常 |
| 语义模型：仓库 `model/cubes/` | 定义维度、可加总指标和加权结案率 | 想理解某个数字怎么算，或增加可查询字段 |
| 查询视图：如 `ResearchSummaryView` | 给图表提供约定好的字段集合 | 新建图表、检查图表到底用了哪份数据 |
| Dashboard | 把查询结果排成图、表和筛选器 | 阅读结论、探索社区、演示项目 |

数据源刷新、模型部署、页面保存是三件事。保存图表不会重新下载 311；提交模型不会自动保证现有图表布局正确；Actions 模型编译成功也不等于线上每个图已验收。

## 按问题选择视图

| 问题 | 视图 | 看什么 |
|---|---|---|
| 全市两期发生了什么变化？ | `ResearchSummaryView` | Requests、Eligible 30d、Closed 30d、Closure 30d Rate；必须明确 Period |
| 五个行政区有何不同？ | `BoroughComparisonView` | Borough、Period、请求量和结案率；图中排除 Unspecified 时注明 |
| 哪个月、哪类服务值得看？ | `ServiceMetricsView` | Month、Agency、Service、Community District；分母随筛选改变 |
| 哪些组合值得调查？ | `OperationalPrioritiesView` | 固定发布的 50 条、两期分母、结案率变化；不是失败排行榜 |
| 哪些证据还缺？ | `ResearchDataStatusView` | Dataset、Status、Coverage、Limitation |
| 哪项政策有何实施证据？ | `PoliciesView` / `PolicyEvidenceView` | 官方链接、日期、原文、阶段；空表不能解释为政策数量为零 |

## 一次正确的阅读顺序

1. 清除旧筛选，确认研究期为 2025-10 至 2026-09，基准期为前一年同季节窗口。
2. 先看请求量，再看 Eligible 30d：结案率的分母不是全部请求量。
3. 结案率用 `SUM(Closed 30d) / SUM(Eligible 30d)`，不可平均各社区百分比。
4. 对比行政区，再固定相同 Agency / Service 比较社区。混合服务构成会影响总率。
5. 打开调查线索，连同两期样本量阅读。50 条名单按结案率降幅排序，不能说是对全市增长的最大贡献者。
6. 最后看政策和来源覆盖。行政结案不证明问题实际解决；相关时间变化不证明政策造成变化。

月份图有两种有效读法：按真实时间画连续 24 个月，或使用十月至九月的共同季节轴叠加两期。直接用真实年月作横轴再按 Period 分线，不能产生同月对齐比较；必须检查现有图表实现。

## 平台操作涉及哪些风险

查询探索用于试字段和筛选；模型编辑涉及指标定义；连接设置涉及数据库授权；部署记录用于确认线上版本；日志用于定位失败；共享设置决定别人能否访问。暂时不需要为了演示更改数据库连接、令牌、计费或公开访问。

不能把登录才能打开的 dashboard 链接当作公开交付。最终需实测观众账号权限，并保留经检查的导出或截图；不得在导出中包含令牌、数据库连接串或原始地址。

## 每次修改后的说明格式

今后每次部署或页面修改均记录：

1. 改了哪个页面、图表、模型或数据库表，以及修改目的。
2. 点击哪个已验证链接可以看到；哪些地方需要登录。
3. 维度、指标、单位、默认筛选、数据日期和分母。
4. 如何操作一个具体筛选，预期看到什么，如何恢复默认。
5. 验证结果、未验收部分、对应 Git 提交或运行链接；必要时给出回退办法。

完整图表字段与验收数字见 `cube-dashboard-guide.md`。本轮只新增说明和验证材料，没有修改线上 Cube。
